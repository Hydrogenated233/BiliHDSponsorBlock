# 封面模式验证

基线：Chrome 扩展 0.17.1，固定源 `b3704f380c1614351f5effdc839b8f44e35d1269` 的 `src/thumbnail-utils/thumbnails.ts`。目标宿主为 HD 2.2.0（2020100），设备 NP03J，Android 14。

## 实现范围

`FullVideoLabels` 和设置界面接受全部六种模式：0 无操作、1 分类标签、2 隐藏卡片、3 悬停揭示的模糊、4 持续模糊、5 实色遮挡。分类与首标签选择沿用既有规则。4／5 拦截被遮挡卡片的点击，3 仅响应鼠标或笔的悬停，不把手指点击改造成额外操作。

模糊与遮挡属于模块自己的 ViewOverlay；不替换宿主点击监听器、图片或渲染效果。快照只在内存中短暂保留，使用有界 CPU 模糊。悬停有 500ms 透明度过渡，实色取宿主主题背景色。切换模式、复用、离屏和解绑时清理所属覆盖层并恢复可见性；从设置返回首页时通过可见性边沿重新定位。

Android 的 CPU 模糊与网页 backdrop-filter 不承诺像素一致。模式 2 使用根视图 GONE；RecyclerView 的网格位置仍由宿主决定，不承诺网页 display:none 的重排结果。适配仍限已定位的 V5 和当前首页 `gk1.p` 卡片，其他承载点仍待补齐。

## 验证层级

纯策略保留原有 100 项内部断言，并覆盖模式范围与分类门控；模糊测试检查边界、透明度、不修改输入及尺寸限制。当前源码共 231 项 JUnit 测试。

初次真实社区正标签卡片上确认了持续模糊、实色遮挡及其点击拦截，隐藏、禁用与恢复也做了实际 UI 检查。该轮悬停效果没有有效命中，未列作悬停通过。

后续可回滚本地响应样本保持同一首页实例，分别切换 4 → 5 → 3 → 2 → 1 → 0 → 1。样本只将当前可见卡片的本地缓存映射为 sponsor，不发送社区写请求。独立临时测试 APK 通过标准 UiAutomation 注入真实鼠标悬停事件：进入时模糊层和标签消失，移出后恢复；两次点击被 4／5 拦截，模式 2 隐藏，0 清除，1 恢复。此结论明确属于本地样本验证，不能冒充社区标签数据正确性测试。

每次样本结束均核对完整设置相等，并在重启缓存所有者前恢复原始标签缓存文件及其 SHA-256。外部 app_process 注入工具被系统终止，未用于通过判定。临时输入 APK 和 DEX 在最终复测后移除，生产 APK 没有测试入口。

最终过渡／主题颜色版本再次通过全部六种模式的实际 UI 样本检查：4／5 点击拦截计数为 1／2，3 的真实鼠标悬停计数增加，2 的隐藏计数为 1，0 清空覆盖层，1 恢复标签，全程卡片错误为 0。完整设置与原标签缓存 SHA-256 均已恢复；临时输入 APK 和 DEX 已移除。

本机 release、lint 与 231 项单元测试通过。干净公开源码构建另见发布核对记录。社区写入在所有测试中保持关闭。
